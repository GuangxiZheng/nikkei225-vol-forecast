# 特徴量候補リスト (モデル拡張のための洗い出し)

作成: 2026-10-16 (2026-10-28: データラベル補正により全検証を再実行・n=440週) /
目的: HAR+VI (rv_d, rv_w, rv_m, vi) を超える特徴量の体系的探索。
**原則**: 追加候補はすべて同じ型 (拡張ウィンドウ・月次再推定のウォークフォワード、
未来参照ゼロ、金曜非オーバーラップ評価) で検証し、OOS R² が改善しなければ採用しない。
特徴量の選別自体にデータスヌーピングを持ち込まないため、候補はこのリストに**事前宣言**する。

## 0. 既存データに未使用の情報 (外部データ不要)

**検証1 実施済み (2026-10-16、詳細は [feature_ext_report.md](feature_ext_report.md))**:
基準 HAR+VI(v2.0仕様) OOS R² +0.386 を再現した上で、**pk5 (Parkinsonレンジ) を加えると
+0.397、3特徴量全部で +0.398** (前半/後半とも改善・ΔMSE +2.1±1.4で有意)。
dsr22・maxz5 は単体では有意な改善にならず不採用。
**採用候補: V2 (+pk5) と V5 (+pk5+dsr22+maxz5)**。
**→ 2026-10-16、ユーザー決定により V2 (+pk5) を本番モデル v2.1 に先行採用**
(検証バッテリー再実行済み: 検証3で h=5 OOS R² +0.397 / アンサンブル +0.395。
検証1・2はv2.0仕様のまま回帰確認に使用し、数値は一切変化なし)。

**OOS確認の仕組み (ロールバック・セーフティネット)**: 仕様は
[feature_oos_spec.json](feature_oos_spec.json) に凍結 (カットオフ 2026-10-15・
観測後の変更禁止)。毎月最初の営業日に `feature_oos_check.py` が自動実行され
(毎日09時の自動化から呼び出し)、カットオフ以降に確定した金曜のみで
「pk5込み vs v2.0基準」の累積評価を続ける。**累積 n≥8 (2027-01-04実行分、n≈10) で
ΔMSE>0 が継続していれば採用維持、<0 に逆転していたら v2.0 へのロールバック判断**。
結果は [feature_oos_log.jsonl](feature_oos_log.jsonl) に蓄積。

| 候補 | 内容 | 検証状況 |
|------|------|---------|
| レンジベース推定量 (pk5) | 高値−安値からParkinson推定 (週次)。終値のみのRVより効率的。OHLCは既に取得済み | **採用候補** — OOS R² +0.386→+0.397 (ΔMSE +2.1±1.4・前後半で安定) |
| 下落半変動率の比率 (dsr22) | ボラは下落時に急騰する非対称性 (レバレッジ効果)。22日分の下落リターンのstd ÷ rv_m | 不採用 — 改善幅 +1.5±1.8 でCIがゼロを含む |
| ジャンプ成分 (maxz5) | 直近5日の最大標準化日次変動 (\|ret\|/σ22)。大幅変動日はその後のボラが上振れる | 不採用 — 改善幅 +0.7±1.0 でCIがゼロを含む |
| 出来高・売買代金 | 薄商い日はスパイクしやすい | **不採用 (データ欠落)** — ソースの出来高は2007年末までしか無い (9026行中1369行) |

## 検証の進め方 (優先順位)

1. **既存データ強化** (dsr22 / pk5 / maxz5) — 取得コストゼロ → `feature_ext_test.py`
2. VIX + 米国株 + USD/JPY の3変数 — stooqでCSV取得
3. イベントダミー — カレンダー作成のみ
4. センチメント系・ガンマ — データ整備コスト大、最後

**正直な期待値**: VIが既に強力なため、外部追加でOOS R²が+0.05〜0.10上がれば良い方。
改善しなければ「その情報は不要」という検証済み知見になる (loto-analysisと同じ型)。
